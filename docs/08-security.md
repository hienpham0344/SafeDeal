# Security Architecture & Threat Model

SafeDeal operates on a **trust-minimized custody boundary**: backend API, database, RPC endpoints, browser sessions, and the Chrome Extension are never permitted custody over user funds. Verified smart contract controls enforce solvency on Avalanche C-Chain; institutional Web2.5 controls protect authentication lifecycle, cryptographic terms parity, encrypted dispute evidence, tamper-evident audit trails, and anti-phishing client isolation.

## 1. On-Chain Threat Controls & Public Verification (`SafeDealEscrow.sol`)

- **Snowtrace/Routescan & Sourcify Verified Source Code**: Live Avalanche Fuji `SafeDealEscrow` (`0xF30E863b0Cfe8fBFE05E65c21878F8B621B3FE29`) publishes byte-for-byte verified Solidity `0.8.28` source code on both **Snowtrace (Routescan)** and **Sourcify**, backed by automated dual-verifier deployment hooks in `blockchain/foundry.toml`, `scripts/deploy-fuji.sh`, and `.github/workflows/contracts-deploy.yml`.
- **Zero Admin Custody / Upgrade Risk**: Contract is non-upgradeable with no `owner`, `pause()`, or `sweep()` backdoor.
- **Pull-Payment Reentrancy & DoS Isolation**: `withdraw()` applies OpenZeppelin `ReentrancyGuard` and zero-before-transfer `Checks-Effects-Interactions`. Reverting receivers only affect their own `withdraw()`, never countersigning payouts.
- **Role Isolation**: Contract enforces `seller != arbiter`, `buyer != seller`, `buyer != arbiter`, and `arbiter != address(0)`.
- **2-of-3 Consensus, Sum Invariant & 14-Day Timeout Escape Hatch**: `submitResolutionVote` requires 2-of-3 matching votes across `[buyer, seller, arbiter]` and checks `buyerAmount <= trade.amount && sellerAmount == trade.amount - buyerAmount`, preventing unilateral arbiter seizure, overpayment, or dust lockup (`arbiter` receives `0`). After 14 days (`DISPUTE_TIMEOUT`), `resolveDisputeByTimeout` enforces a deterministic 50/50 split (`buyerAmount = trade.amount / 2`, `sellerAmount = trade.amount - buyerAmount`) so funds cannot be held hostage. Stateful Foundry invariant fuzzing (`EscrowInvariant.t.sol`) exercises seller-initiated disputes, interleaved 2-of-3 vote overwrites, and timeout settlement.
- **Direct Transfer Prevention**: `receive()` and `fallback()` revert immediately (`DirectTransfersNotAllowed`).

## 2. Backend & Web API Institutional Security Controls

| Threat Vector | Implemented Control | Primary Implementation |
|---|---|---|
| **Wallet Impersonation & Replay** | EIP-4361 (SIWE) message parsing checks domain, URI, chainId, expiry, and secp256k1 public-key recovery via `k256` (canonical and normalized `v` values). Challenges expire after `NONCE_TTL_SECONDS`, are consumed atomically once in SQL (`AuthNonceRepository::consume_once`), and expired rows are swept by `CleanupOrphanDraftsUseCase`. | `SiweAuthService`, `SiweMessageParser`, `K256SignatureVerifier` |
| **Stateful `jti` Logout Revocation & Bearer-First Dual Session** | Every HS256 JWT embeds a unique UUID v4 `jti` claim. `POST /api/v1/auth/logout` persists `(jti, wallet_address, expires_at)` into PostgreSQL `revoked_sessions` (cached in memory and purged after expiry), causing any replayed cookie or `Authorization: Bearer` token to fail immediately with `401 UNAUTHORIZED`. `session_auth_middleware` evaluates `Authorization: Bearer` first (`via_cookie = false`) and falls back to `HttpOnly` `safedeal_session` cookies (`via_cookie = true`), eliminating cross-origin 3P cookie / Bearer CSRF races while strictly enforcing Double-Submit CSRF (`safedeal_csrf` + `X-CSRF-Token`) and `Sec-Fetch-Site` download isolation on cookie-authenticated requests. | `JwtSessionService`, `session_auth_middleware`, `double_submit_csrf_middleware`, `revoked_sessions` |
| **Proxy-Safe Client-IP Extraction & Multi-Tier Per-Wallet Rate Limiting** | `X-Forwarded-For` / `X-Real-Ip` headers are honored only when `AUTH_TRUST_PROXY_HEADERS` is enabled AND `ConnectInfo<SocketAddr>` originates from loopback, RFC 1918 private subnets, IPv6 ULA (`fc00::/7`), or Carrier-Grade NAT (`100.64.0.0/10` for Railway Envoy). Rate-limit maps evict expired windows before active keys to defeat cache-flush attacks, pairing IP throttling on `/auth/nonce` & `/auth/verify` with authenticated **per-wallet quotas** on expensive mutations (`POST /api/v1/deals/drafts` 30/min, `POST /api/v1/deals/{id}/sync` 30/min, `POST /api/v1/disputes/{id}/evidence` 20/min). | `RateLimitConfig`, `AuthRateLimitState`, `middleware.rs` |
| **Tamper-Evident SHA-256 Hash-Chained `audit_logs`** | Each `audit_logs` record computes a deterministic SHA-256 `entry_hash` over `prev_hash` (`'GENESIS'` for root) + action, actor, resource, correlation ID, JSON details, and millisecond timestamp. Inserts are serialized atomically in PostgreSQL and guarded by a `BEFORE UPDATE OR DELETE ON audit_logs` trigger that rejects mutations or deletions at the database layer. | `audit_repo.rs`, `20261126000003_security_revocation_and_audit_chain.sql` |
| **AES-256-GCM Evidence Encryption-at-Rest, Magic-Byte & SHA-256 Integrity** | Uploaded dispute evidence enforces MIME allowlisting (`image/png`, `image/jpeg`, `application/pdf`, `text/plain`), **magic-byte signature inspection**, UUID filenames, canonical path containment, and plaintext **SHA-256 integrity verification** on upload and download. When `EVIDENCE_ENCRYPTION_KEY` is configured, files are encrypted at rest using pure-Rust **AES-256-GCM** (`SDE1` header + 12-byte random nonce + authenticated tag; zero `openssl-sys`) plus optional S3 SSE (`x-amz-server-side-encryption: AES256`). Downloads enforce strict participant/arbiter ACL (`403`), `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, and `Cache-Control: no-store`. | `LocalEvidenceStorageAdapter`, `S3EvidenceStorageAdapter`, `DisputeUseCase` |
| **Off-Chain Terms Substitution & RPC Finality Verification** | Frontend (`canonical-terms.ts`), Chrome Extension (`extension/shared/canonical-terms.js`), and Backend (`CanonicalTermsHasher` in `canonical_terms.rs`) independently compute RFC 8785 Canonical JSON SHA-256 `termsHash`. `AlloyBlockchainGateway::inspect_transaction` always verifies `receipt_block <= latest_block` and required block confirmations (`confirmations_required >= 1`) against `get_block_number()`, while `ArbitrationUseCase` cross-checks live `fetch_trade` state on settlement. | `CanonicalTermsHasher`, `AlloyBlockchainGateway`, `ArbitrationUseCase` |
| **DB Pool Exhaustion Under Slow RPC** | External Alloy JSON-RPC calls always execute outside PostgreSQL transactions (`UnitOfWork::in_tx` wraps short SQL reads/writes only), and `S3EvidenceStorageAdapter::is_storage_ready` caches readiness probes for 10s. | `BindDealTransactionUseCase`, `SyncDealUseCase`, `BlockchainEventIndexerService` |
| **CSP, HSTS & Production Secret Fail-Fast** | `AppConfig::validate` aborts startup in `prod`/`staging` on weak/placeholder `JWT_SECRET`, insecure cookies, wildcard/loopback CORS, or localhost SIWE/RPC endpoints. Backend API (`security_headers_middleware`) and Frontend hosting (`firebase.json`, `frontend/nginx.conf`) enforce `Strict-Transport-Security` (HSTS), `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, and `Referrer-Policy: strict-origin-when-cross-origin`. `.github/workflows/secrets-scan.yml` runs Gitleaks across commit history. | `AppConfig::validate`, `security_headers_middleware`, `firebase.json`, `frontend/nginx.conf`, `secrets-scan.yml` |

## 3. Frontend Zero-Trust Verification & Chrome Extension Anti-Phishing Controls

- **3-Way Zero-Trust On-Chain Verification (`DealDetailsPage.tsx`, `useEscrowActions.ts`, `DisputeConsensusPanel.tsx`)**:
  - The Web App independently recomputes the browser SHA-256 `termsHash` and compares Backend API deal fields against live Avalanche C-Chain `SafeDealEscrow.getTrade(bytes32)` (`termsHash`, `amount`, `seller`, `arbiter`, `status`) and `getDisputeVotes(bytes32)`.
  - Matching deals display an emerald **`3-Way Verified (Browser SHA-256 = API = Avalanche Contract)`** badge; any API/chain discrepancy or spoofed funded state surfaces a red **`On-Chain Integrity Mismatch — Actions Blocked`** / **`Unverified On-Chain Escrow`** alert and disables state-changing actions (preventing a compromised API from tricking a seller into delivering goods on an unfunded escrow).
  - Pre-write safety checks verify contract bytecode existence (`publicClient.getBytecode`) and decode custom Solidity reverts into actionable messages; unauthenticated visitors on `/deals/:id` also receive a live read-only On-Chain Contract Verification card directly from RPC.
- **Verified Neutral Arbiter Shield, SIWE Anti-Phishing & Address-Poisoning Guards**:
  - `CreateDealPage.tsx` and `DealDetailsPage.tsx` verify `arbiter` against `env.defaultArbiterAddress`, rendering an emerald **Verified Neutral Arbiter** shield or an amber **Custom External Arbiter (Verify Neutrality — 2-of-3 Consensus Power)** warning, alongside 4-char prefix+suffix vanity lookalike address-poisoning alerts and USD/VNĐ sanity estimates.
  - `AuthSessionProvider.tsx` verifies `challenge.message` contains both `window.location.host` and the connected wallet address before calling `signMessageAsync`.
- **Chrome Extension MV3 Anti-Phishing Domain Shield & Sender Isolation (`extension/`)**:
  - **Anti-Phishing Domain Shield (`extension/content/deal-verifier.js`)**: Parses every `/deals/0x...` link with `new URL(anchor.href, window.location.origin)` and checks `parsedUrl.origin` against allowlisted official SafeDeal origins (`https://avalanche-9b099.web.app` and local dev ports). Links pointing to untrusted/lookalike domains never render a green `FUNDED` badge — instead injecting a high-contrast red Shadow DOM alert: **`[⚠️ SafeDeal Security Alert: Unofficial Phishing Domain!]`**. Link scanning is capped (`MAX_LINKS_PER_SCAN = 100`), deduplicated via a 60s TTL `Map` cache, and guarded with `Object.hasOwn`.
  - **Sender Isolation, Metadata Stripping & Zero Cookie Leakage (`extension/service-worker.js`, `extension/shared/rpc-client.js`, `extension/sidepanel/sidepanel.js`)**: Enforces explicit MV3 `content_security_policy` (`script-src 'self'; object-src 'none'; base-uri 'none';`), validates `sender.id === chrome.runtime.id`, restricts privileged actions (`REQUEST_MARKETPLACE_SCAN_PERMISSION`, `CLEAR_BADGE`, `REFRESH_WATCHED_DEALS`, `COMPUTE_TERMS_HASH`) to trusted extension UI pages, strips private off-chain `metadata` from content-script `VERIFY_DEAL` responses, dynamically registers `content/deal-verifier.js` via `chrome.scripting.registerContentScripts` only after user opt-in, omits all ambient cookies (`credentials: "omit"`), and validates `https:` / loopback schemes and EVM addresses before `fetch` or `chrome.tabs.create`.
